基础约定

Focus Ingestion Engine 是本地注意力摄取与焦点归因引擎。所有接口以 JSON 交互。

项说明
Base URLhttp://127.0.0.1:17879（容器内绑定 0.0.0.0:17879；本文档与测试台默认同源）
Content-Type请求体为 JSON 时须带 content-type: application/json
字符编码UTF-8
鉴权无。网络暴露面由绑定地址（FIE_HOST）控制
CORS仅对本机来源（localhost / 127.0.0.1 / [::1] 及 file:// 的 null 源）放行并处理预检 OPTIONS
核心链路严格单向：脱敏 → 幂等写入 → 创建 run → 提取 → 匹配 → 决策 → 写 Focus/check-in。任何写入日志/输出的内容都先经脱敏层，摘要中的邮箱、Token、Bearer、IP、手机号、/Users/* 路径会被替换为 [REDACTED_*]。

事件对象 AttentionEvent

摄取接口的请求体。source + sourceEventId 组成幂等键（数据库 UNIQUE 约束），重复提交返回 duplicate 且不写新 check-in。

字段类型说明
source 必填string事件来源，如 codex / git-hook / ci / agent
sourceEventId 必填string来源内唯一的事件 ID，与 source 组成幂等键
occurredAt 必填stringISO 8601 且带时区偏移，如 2026-07-09T09:00:00+08:00。活跃度/趋势以此为准
type 必填string形如 domain.action 的事件类型，如 conversation.finished、git.commit.created、automation.completed
project 可选string项目名。命中候选 Focus 项目名时贡献最高权重（+50）
summary 可选string一句话摘要。参与关键词提取，写入前脱敏
content 可选string原始正文。按隐私模式决定是否保留，不会出现在查询响应中
metadata 可选object任意键值。其中 files（字符串数组）用于文件维度的跨工具匹配

摄取结果 IngestResult

/v1/events/ingest 的响应体；批量接口的每条 results[] 同构（另带 source/sourceEventId）。

字段类型说明
status"accepted" | "duplicate"是否被受理；重复事件为 duplicate
deduplicatedboolean是否命中幂等去重
decision"skip" | "check_in" | "create_and_check_in" | null决策结果；重复事件为 null
focusIdstring | null命中/新建的 Focus ID；skip 或重复时为 null
runIdstring本次 ingestion run 的 ID，可用于查询详情
reasonstring | null决策可解释理由
lowConfidenceboolean分数落在 [T_create, T_match) 复核区间时为 true

错误格式

{
  "error": {
    "code": "invalid_event",
    "message": "事件格式无效",
    "details": [ { "path": "occurredAt", "message": "..." } ]
  }
}
codeHTTP场景
invalid_event400单条摄取的事件校验失败
invalid_batch400批量请求体校验失败（如 events 为空或超过 100 条）
run_not_found404指定 run 不存在
page_not_found404静态页缺失
internal_error500服务端内部错误

POST/v1/events/ingest

摄取单条事件，返回决策结果。

202 已受理 200 重复（幂等命中） 400 invalid_event 500 internal_error

请求示例

curl -X POST http://127.0.0.1:17879/v1/events/ingest \
  -H 'content-type: application/json' \
  -d '{
    "source": "codex",
    "sourceEventId": "pay-codex-001",
    "occurredAt": "2026-07-09T09:00:00+08:00",
    "type": "conversation.finished",
    "project": "支付网关重构",
    "summary": "实现支付网关的路由分发骨架，重构原有单体下单逻辑。",
    "metadata": { "files": ["src/payment/gateway.ts", "src/payment/router.ts"] }
  }'

响应示例（202）

{
  "status": "accepted",
  "deduplicated": false,
  "decision": "create_and_check_in",
  "focusId": "focus_xxx",
  "runId": "run_xxx",
  "reason": "无匹配候选，创建新 Focus",
  "lowConfidence": false
}

POST/v1/events/batch

批量摄取（1–100 条）。逐条隔离：任一条失败不影响其余，失败计入结果。

202 已受理 400 invalid_batch 500 internal_error

请求体

{ "events": [ AttentionEvent, ... ] }   // 1 ≤ 长度 ≤ 100

响应示例（202）

{
  "status": "accepted",
  "accepted": 1,
  "duplicates": 1,
  "failed": 0,
  "results": [
    { "source": "ci", "sourceEventId": "batch-1", "status": "accepted", "decision": "check_in", "runId": "run_a", ... },
    { "source": "ci", "sourceEventId": "batch-1", "status": "duplicate", "deduplicated": true, "runId": "run_b", ... }
  ]
}

GET/v1/runs

列出 ingestion run（按事件 occurredAt 倒序）。

查询参数默认说明
limit50返回条数，上限 200

响应示例（200）

{
  "runs": [
    {
      "id": "run_xxx", "status": "accepted", "decision": "check_in", "reason": "...",
      "source": "git-hook", "source_event_id": "pay-commit-001",
      "event_type": "git.commit.created", "occurred_at": "2026-07-09T10:30:00+08:00",
      "created_at": "2026-07-09T10:30:01.000Z"
    }
  ]
}

GET/v1/runs/:id

单次 run 详情，含事件（脱敏后摘要）、决策候选与 check-in。不暴露原始正文。

200 404 run_not_found

响应示例（200）

{
  "run": {
    "id": "run_xxx", "status": "accepted", "decision": "check_in",
    "reason": "...", "candidates": [ { "id": "focus_x", "name": "...", "score": 75, "reason": "..." } ],
    "error": null, "created_at": "...", "updated_at": "...",
    "event": {
      "id": "evt_xxx", "source": "agent", "sourceEventId": "pay-agent-001",
      "occurredAt": "...", "type": "conversation.finished", "project": "支付网关重构",
      "summary": "实现登录令牌轮换。联系人 [REDACTED_EMAIL]，临时密钥 [REDACTED_TOKEN] ...",
      "metadata": { "files": ["src/payment/auth.ts"] }, "createdAt": "..."
    },
    "checkin": {
      "id": "chk_xxx", "notes": "...", "blocker": null, "nextAction": null,
      "createdAt": "...", "focus": { "id": "focus_x", "name": "...", "project": "支付网关重构" }
    }
  }
}
可用于核对脱敏：T6 用例摘要含邮箱/Token/IP/手机号/家目录路径，返回时应全部呈现为 [REDACTED_*]。

GET/v1/focuses

列出 Focus（按 last_activity_at 倒序）。

查询参数默认说明
limit50返回条数，上限 200
includeArchivedfalse1 或 true 时包含已归档/合并的 Focus

响应示例（200）

{
  "focuses": [
    {
      "id": "focus_xxx", "name": "支付网关重构", "project": "支付网关重构",
      "keywords": ["重构", "实现"], "status": "active", "merged_into": null,
      "last_activity_at": "2026-07-09T14:00:00+08:00",
      "created_at": "...", "updated_at": "..."
    }
  ]
}

GET/v1/trend

按事件 occurredAt 所在日历日聚合的活跃度趋势（排除软删 check-in）。

查询参数默认说明
days30回溯天数，上限 365
focusId—仅统计指定 Focus

响应示例（200）

{
  "trend": [
    { "date": "2026-07-09", "checkins": 4, "focuses": 1 }
  ]
}

附录：匹配打分与决策

匹配器为每个候选 Focus 打分，取分数最高者进入双阈值决策。

信号加分
项目名匹配（project）+50
Focus 名命中+30
每个关键词命中+10
文件路径完全一致 / 同目录 / 同文件名+25 / +8 / +4（路径维度上限 +50）
近期活跃（≤7 天）+5
阈值行为
score ≥ T_match（默认 50）check_in 高置信归入
T_create（默认 25）≤ score < T_matchcheck_in 并标 lowConfidence 复核
无候选但事件实质create_and_check_in 新建 Focus
非实质（trivial）skip 仅记录 run
阈值可用环境变量 FIE_T_MATCH / FIE_T_CREATE 调整；若 T_create > T_match 会收敛到相等（低置信区间为空）。
